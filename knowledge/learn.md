# 失敗の記録(learn)  版: v1 / 2026-10-15

## 記録の型(必ず4項目)
- 症状: 何が起きたか(見逃し、誤抽出、表示のずれ など)
- 原因: 分かった原因
- 再発防止: 次に変えること
- 対応したファイル: 変更した knowledge/ や config/ のファイル名

## 記録の例(架空)
- 症状: 店頭抽選の受付時間を1日ずれて表示した。
- 原因: 夜間をまたぐ受付の時刻を、当日扱いにしていた。
- 再発防止: domain.md の時刻のパターンに「夜間をまたぐ」を明記。Verifier で日付の跨ぎを確認。
- 対応したファイル: knowledge/domain.md, scripts/validate.py

## 記録
### 2026-11-02 PRの検証が赤になった(validate-data #9)
- 症状: 承認で作られたPR #5の検証が赤。同じブランチを手元で検証するとOK。
- 原因: ボットが作ったPRのチェックが実行されない仕組み(下の「ボットのPRで検証が動かない」を参照)。当初は「一時的な失敗」と判断したが、誤りだった。
- 再発防止: 下の項目のとおり、承認の処理の中で検証し、結果をPRに付ける。
- 対応したファイル: docs/status.json, docs/NEXT_ACTIONS.md

### 2026-11-02 商品マスターの実装
- 症状: 画像付きの取込を試す前に、テスト用の本文を `sed` で削ると、画像URLの行が別の項目に混ざって誤判定した。
- 原因: 見出しと値の行を、見出しだけ消して値を残した(テスト側の誤り)。
- 再発防止: 取込の本文は、`sed` ではなく Python で組み立てて検査する。作業フォルダを汚さないよう、コピーで試す。
- 対応したファイル: scripts/products_lib.py, scripts/apply_intake.py
- 補足: この作業環境では npm が外部に接続できず、jsdom でのサイト描画テストはできなかった。構文の確認までにとどめ、公開前に実機で確認する。

### 2026-11-02 ボットのPRで検証が動かない
- 症状: 承認で作られたPR(#5、#7)の validate-data が、ジョブが1件も動かないまま、action_required(のち failure)になる。人が再実行すると通る。
- 原因: ボット(GITHUB_TOKEN)が作ったPRは、通常のチェックが実行されない。以前の「一時的な失敗」という判断は誤りだった。
- 再発防止: 承認の処理の中で validate.py を実行し、その結果をPRのチェック(コミットの状態)として付ける。Actions 設定の変更は、この作業環境の経路ではできない。
- 対応したファイル: .github/workflows/approve-intake.yml

### 2026-11-02 店舗のXアカウントの確認
- 症状: 検索だけでは、公式アカウントの一覧ページに届かないことがある。
- 原因: 検索結果が公式ページを返さない。公式サイトの直接取得は許可リスト外で失敗するサイトがある。
- 再発防止: 「(社名) SNS公式アカウント一覧」の検索結果から、公式ドメインのページを選んで取得する。公式ページで確認できないアカウントは登録しない。
- 対応したファイル: data/shops.yaml
